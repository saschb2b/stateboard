Once a board has a screen and a few regions, you have two ways to get it in front of someone.

## The share link

Every board has one or more public read-only URLs of the form `/share/{token}`.

- The token is a random 24-character string, not the board's name — renaming a board never changes or breaks a link you've already sent.
- **Links are revocable, and you can mint as many as you like.** A board gets its first link automatically when you create it. Add more from **Board settings → Share links**, each with an optional label ("Exec review", "QA") so you can tell them apart later, and revoke any one of them the moment it's been forwarded somewhere it shouldn't be. Revoking is immediate and doesn't touch the other links.
- Anyone with the link can read the board — public and login-free by design, so a stakeholder reads it in seconds. Keep this in mind when uploading sensitive screenshots.
- The share view strips every editor affordance: no upload, no draw, no delete. Tooltips on hover still show labels and notes.

Choose **Share screens → Copy share link** in the screen toolbar. The same menu offers **Open share view** and **Manage links**, including at narrow widths.

The development build also exposes **Board settings** from the product workspace. Open **Share links** there to manage visual links. Use the named board breadcrumb to return to the product overview. To change the board's name or description, choose **Edit board** beside its product name or in the editor's **More board options** menu. These changes preserve existing share URLs.

<Callout type="warn">
  Treat the share URL like a Google Drive "anyone with the link" share. The
  editor is gated by your OIDC provider with `owner` / `editor` / `viewer`
  roles, but share links stay public on purpose — that's how an exec reads a
  board without an account.
</Callout>

## Present mode

Choose **Present** in the screen toolbar or share view. The editor keeps this control in its toolbar at narrow widths. Press **`P`** outside interactive controls to open it with the keyboard. Present mode shows the current screen without the editor header, sidebars, or tabs.

### Keyboard shortcuts

| Key                  | Action                                                  |
| -------------------- | ------------------------------------------------------- |
| `←` / `→`            | Previous / next screen                                  |
| `Space` / `PageDown` | Next screen                                             |
| `PageUp`             | Previous screen                                         |
| `Home` / `End`       | Jump to first / last screen                             |
| `F`                  | Toggle browser fullscreen                               |
| `Esc`                | Exit Present mode (and exit fullscreen first if active) |

### What Present mode shows

- The current screen, letterboxed to the largest size that fits the window.
- All regions painted with their state colors and labels.
- A small bottom strip with the screen name and a `3 / 8` counter.
- A top strip with totals: number of `shipped` / `mock` / `missing` regions across the board.

After ~2.5 seconds without mouse movement, the chrome fades away (and the cursor hides) so the screen is the only thing left. Wiggle the mouse to bring it back.

### Tooltips still work

Stakeholders can hover any region during the presentation to see its label and notes. No need to leave Present mode to dig in.

## Workflow that works well

1. Edit screens and regions until the board reflects reality.
2. Hit **Present** for the quarterly review (or send the share link if it's async).
3. After the review, take corrections back into the editor while they're fresh.
4. Next quarter, the board picks up where you left off, no slide deck to rebuild.
